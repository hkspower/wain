## 1. Critical: checkout was down (fixed today)

The live code (`api/store.php`, md5 = repo HEAD) claims stock with
`inventory_version = inventory_version + 1`. The live database had never run
`inventory.mysql.sql`, so that column did not exist.

- **Every order for a sized product returned 500 `failed`.** All 46 listed
  products are sized, so no order could be placed at all.
- Reproduced in the sandbox: with the live schema the order returns 500.
  With `inventory.mysql.sql` applied it returns 200.
- The last order on file is from 2026-09-30, 33 days ago.
- The same gap broke three admin screens with 500s: Stock (`r=variants`:
  unknown column `unit_cost_kwd`), stock movements (no `inventory_movements`
  table) and admin recovery codes (no `admin_recovery_codes` table).

**Fix, approved by the owner and applied at 15:06Z:**

- Ran `inventory.mysql.sql` and `admin-recovery-codes.mysql.sql`. Both are
  additive and safe to run twice; the sandbox showed that.
- **Backup:** `/docker/sporta/backups/manual-20261102T1506Z-inventory-migration/`
  - `product_variants.json`: 172 rows.
  - `admin_users.json`: 1 row.
  - Mode 0600.
- **Verified:**
  - Variants and units are unchanged (172 / 1,236).
  - The stock claim and the cancel release now prepare.
  - The admin Stock query runs (172 rows).
  - One real stock claim was run inside a transaction and then rolled back.
    It took the row, and the shelf came back exactly as it was. No order was
    created.
- **Schema diff after the fix:** nothing the repo's migrations define is
  missing on the live database.
