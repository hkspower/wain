`apache-sporta-1` (image `apache-sporta`, Apache 2.4 + PHP, healthy). It is running in
the `apache` project, but the `apache` compose file **has no `sporta` service** — the
container is an orphan from an earlier version of that file. A `docker compose up
--remove-orphans` or an "Update project" on `apache` could stop the live shop.

`www.sporta.com.kw`. It fails because its image was never built.

## Fixes applied 2026-10-31 ~12:00 UTC (backups kept, shop 200 throughout)
- **3 — `.well-known` 403:** `site/.htaccess` `<FilesMatch "^\.">` -> `"^\.(?!well-known$)"`.
  Cause: the folder does not exist, so Apache matched the deny against `.well-known`
  itself. Now `/.well-known/hostinger-challenge/x` = 404; `/.env`, `/.git/config`,
  `/.htaccess`, `/api/.x` still 403. Backup: `/docker/sporta/htaccess.bak-claude-20261031T1200Z`.
  Same change in `sporta-web/public/.htaccess`.
- **1 — "orphan":** it was not one — the container runs from the base file PLUS
  `/docker/sporta/apache-service.override.yml`, which the Hostinger panel never shows.
  The sporta service is now merged into `/docker/apache/docker-compose.yml`; compose
  config hashes of all five services are identical to before, so nothing restarted.
  Backup: `/docker/apache/docker-compose.yml.bak-claude-20261031T1200Z`.
- **2 — stopped `sporta` project:** obsolete (the override's own comment says not to run
  it beside the live router). Exited container removed; compose file renamed to
  `docker-compose.yml.retired-claude-20261031T1200Z`, so the project is gone from the
  panel and a panel "Delete" can no longer wipe `/docker/sporta` (the live site).
- Pre-existing drift, NOT changed: running sporta, wain and almuhallab containers carry
  older config hashes than their files, so the next `up` of the apache project will
  recreate those three containers.
