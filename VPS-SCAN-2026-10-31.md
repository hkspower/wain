## Backend login scan (`/backends`, 13:15–13:20 UTC; read-only, no failing logins sent)
Done by reading the live `api/admin.php` and `api/store.php`, and by sending requests from
inside `apache-sporta-1` to `127.0.0.1` with `Host: www.sporta.com.kw` and
`X-Forwarded-Proto: https`.

**Holds up**
- `/backends`: 200, `X-Robots-Tag: noindex`, CSP `script-src 'self'`, `frame-ancestors 'self'`,
  `Referrer-Policy: no-referrer`, HSTS. `robots.txt` disallows it. `/admin` → 404 (no redirect,
  as intended).
- Session cookie `__Host-sporta_admin`: `Secure; HttpOnly; SameSite=Strict`, no Max-Age. PHP
  runs `use_strict_mode`, `use_only_cookies` and `use_trans_sid=0`.
- CSRF: `?r=login` without `X-Sporta-Admin: 1` → 400 `bad_request`. `?r=session`, `?r=orders`
  and unknown routes → 401 `not_signed_in` with `no-store`. No route list leaks.
- Lockout is per account: 5 failures → a 15-minute lock, set inside MySQL in one statement.
  A dummy-hash `password_verify` runs for unknown emails (no timing oracle), and the
  threshold reply is the same for real and unknown emails.
- 2FA: one admin account, **TOTP on**, 2 failed attempts on record, not locked. The code step
  expires after 300 s and is tied to a fingerprint of the password hash. Recovery codes are
  accepted.
- Google sign-in is not configured (`google_available: false`). `store.php` and
  `config-path.php` → 403.

**Findings**
1. **Every visitor shares one IP, so the per-IP limits are effectively global.**
   - Cause: Traefik runs on the host network and Apache sees every request from the bridge
     gateway **172.16.1.1** (245 of the last 400 log lines). `trusted_proxy_ips` is absent
     from `private/api-config.php`, and `mod_remoteip` is off. So `store_client_ip()` returns
     172.16.1.1 for the whole internet.
   - What breaks:
     - 20 wrong passwords from anyone block **all** admin sign-in for the window (login IP
       bucket).
     - 10 bad codes block every TOTP entry for 5 minutes.
     - The 8 password-reset requests per 15 minutes are shared by everyone.
     - The `admin` limit of 240 requests a minute is shared too.
     - The customer and birthday throttles have the same problem.
   - What doesn't: no account can be guessed into, because the per-account lock still works.
     The real risk is that anyone can lock everyone out.
   - Fix: add `'trusted_proxy_ips' => ['172.16.1.1'],` to `private/api-config.php`. This is
     safe: no container publishes port 80 (`docker ps` shows only `80/tcp`), so only the host
     and Traefik can reach Apache from that address. `store_client_ip()` walks
     X-Forwarded-For from the right, so a spoofed value from a client can't win.
2. **`?r=google_status` throws a database error for the signed-in admin.** It selects
   `admin_users.google_sub`, but that column doesn't exist in the live schema, and the compiled
   `AdminApp` calls this route. The fix is an additive column
   (`google_sub varchar(255) null unique`), or leave it until Google sign-in is wanted.
3. `config.example.php` is in the web root (reachable status not checked). It holds no
   secrets, but it is a map of every config key.
