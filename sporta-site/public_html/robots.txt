# Sporta — crawler policy. All search + AI engines welcome on the storefront.
#
# NOTE ON STRUCTURE: a crawler obeys ONE group — the one matching its own name,
# or the wildcard group if no name matches. It does not read the wildcard group
# as well. So the Disallow lines have to be repeated in EVERY group. They were
# previously only in the wildcard group, which meant every named AI bot below
# was told "Allow: /" and nothing else, and was free to crawl /backends and the
# payment endpoints. Add a bot, add its five Disallow lines with it.
#
# WHY /admin IS LISTED SEPARATELY FROM /backends. They are the same panel: an
# .htaccess rule 302s /admin and /admin/anything to /backends, because the
# panel is a real route and typing the obvious name should reach it. That makes
# /admin a SECOND PUBLIC SPELLING, and a crawler told to avoid /backends knows
# nothing about it — it follows the redirect and indexes the sign-in page under
# the name it started from. The alias costs one line here; seeing it in a
# search result costs rather more. Found by scripts/robots-sitemap-test.mjs.
#
# AND /api/. Everything under it is JSON served no-store, so none of it is a
# page anyone should reach from a search result — but ?r=products is a full
# catalogue dump and ?r=stock is a scan of every size row, and a crawler that
# finds one will re-fetch it on a schedule forever. The rate limits bound how
# fast that can go; this is what stops it starting. The three image routes sit
# under /api too and are excluded with the rest, which is right: they are
# already reachable through the pages that embed them, which is where a crawler
# should meet an image anyway.

User-agent: *
Allow: /
Disallow: /backends
Disallow: /admin
Disallow: /api/
Disallow: /knet/
Disallow: /pay/
