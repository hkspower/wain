# JavaScript scan, 2026-11-19 (read-only)

Owner: "scan javasript". Scope: the add-on scripts that run on top of the compiled storefront and admin: `boot.js`, `config.js`, `birthday.js`, `sporta-features.js`,
`sporta-admin-brands.js` (the real code; on the live site a 1 kB loader names it and it loads on `/backends` only), `sporta-footer-call.js`, `sporta-gov-autopick.js`,
`sporta-clock.js`, `sporta-checkout-a11y.js`, `sporta-catalogue.js` and `sw.js`. The compiled React bundle is not in scope. Nothing was changed on the live site and no
add-on file was edited by this scan.

Tool: `node scripts/js-scan.mjs` (`STATIC_ONLY=1` for the first half). **Static** = the files read as text with comments and strings removed. **Runtime** = the real compiled
pages (the capture of the live storefront) with every add-on loaded, 7 pages x Arabic and English x 390 and 1280 px = 28 loads, 5.5 s each, one bag line in the cart.

## Result

**No uncaught script error on any of the 28 loads, no syntax error in any file, no `eval`, no `document.write`, no `innerHTML` / `outerHTML` / `insertAdjacentHTML`, no `console.*`
call left in.** The findings below are about how a future fault would behave, not about a fault today.

## Method notes

- The "no closing `catch`" count is a heuristic (the last token before a block's closing `})()` is a `catch` clause or not). A block that guards each inner step with its own `try` is counted as unguarded, so 59 is the upper bound; the five "no `try` at all" blocks are exact.
- The runtime pass counts observers, intervals and long tasks by the file named in the call stack, so the compiled bundle's own are listed as `bundle`.
- Each "Failed to load resource" line was attributed to a URL (status and folder, or the outside host) with the subset run `PAGES=/,/shop,/product/sculpt-jacket-black,/account LANGS=ar WIDTHS=390`: 404 under `/images/products/` (31), `/api/` (11), `/cats/mobile/` (3), `/assets/` (2) and 10 requests to `use.typekit.net`. The scan's exit code now follows uncaught page errors only (the resource lines are reported, not failed).
