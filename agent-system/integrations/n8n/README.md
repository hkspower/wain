# ربط موصول بـ n8n

النظام يدفع أحداثه إلى وجهة خارجية، وn8n يستقبلها ويتصرّف. أول ما بُني على
هذا الطريق: **إرسال رابط المهمّة للكابتن على واتساب تلقائيًا** بدل نسخه يدويًا
من اللوحة.

## لماذا الدفع لا الاستطلاع

- **الفوري يهمّ.** الرابط يجب أن يصل الكابتن لحظة إسناد الطلب، لا بعد دورة
  استطلاع كل خمس دقائق.
- **الاستطلاع يحتاج مفتاح مدير مقيمًا في n8n** يقرأ كل شيء في النظام. الدفع
  يرسل ما يخصّ الحدث وحده، فلا يوجد مفتاح دائم بصلاحية كاملة خارج النظام.

## الحدث

`link.created` — يُدفع عند `POST /api/orders/:id/link`:

```json
{
  "event": "link.created",
  "sent_at": "2026-08-15T18:31:00.000Z",
  "data": {
    "link":  { "url": "https://ops.mawsool.com.kw/l/<token>", "expires_at": "…" },
    "agent": { "id": 2, "name": "أحمد الكندري", "phone": "+96590001111" },
    "order": {
      "id": 41, "code": "MW-4001", "status": "assigned", "status_label": "مُسند لمندوب",
      "customer_name": "منى الصباح", "customer_phone": "+96599887766",
      "pickup_address": "…", "dropoff_address": "…", "governorate": "حولي",
      "cod_amount": 12.5, "agent_earning": 1.8, "priority": "normal", "notes": "…"
    }
  }
}
```

الحمولة مكتفية بذاتها: كل ما تحتاجه رسالة واتساب حاضر فيها، فلا يعود n8n
يسأل النظام ولا يحتاج صلاحية قراءة عليه.

### الترويسات

| الترويسة | المعنى |
|---|---|
| `X-Mawsool-Event` | اسم الحدث |
| `X-Mawsool-Timestamp` | طابع زمني بالمللي ثانية |
| `X-Mawsool-Signature` | `sha256=<hmac>` على `«الطابع».«الجسم»` بسرّ `MAWSOOL_WEBHOOK_SECRET` |
| `Authorization` | رمز ثابت اختياري (`MAWSOOL_WEBHOOK_AUTH_VALUE`) يتحقّق منه n8n باعتماده |

الطابع الزمني داخل التوقيع لا خارجه، فإعادة بثّ طلب قديم مُلتقَط لا تنتج
توقيعًا صالحًا. والمقارنة عند المستقبل يجب أن تكون ثابتة الزمن.

> **ترويسات HTTP لا تحمل إلا ASCII.** رمز مصادقة بحروف عربية يجعل الإرسال
> يفشل قبل أن يبدأ — يظهر سببه في «صادر الأحداث» ولا يضيع الحدث.

## الضبط

في `.env` عند النظام:

```
MAWSOOL_WEBHOOK_URL=https://<حسابك>.app.n8n.cloud/webhook/mawsool-link
MAWSOOL_WEBHOOK_SECRET=<openssl rand -hex 32>
MAWSOOL_WEBHOOK_AUTH_VALUE=<openssl rand -hex 24>
MAWSOOL_PUBLIC_URL=https://ops.mawsool.com.kw
```

في n8n:

1. أنشئ سير العمل من `mawsool-link-to-captain.workflow.js`.
2. عقدة **«رقم المرسِل»**: ضع `Phone Number ID` من Meta.
3. اعتماد **Header Auth**: الاسم `Authorization`، والقيمة نفس
   `MAWSOOL_WEBHOOK_AUTH_VALUE`.
4. اعتماد **WhatsApp Business Cloud** موجود مسبقًا.
5. فعّل سير العمل، وانسخ رابط الويبهوك إلى `MAWSOOL_WEBHOOK_URL`.

## ماذا لو تعثّر الإرسال

الحدث يُكتب في الصندوق **قبل** محاولة الدفع، فلا يضيع:

- اللوحة تعرضه في `GET /api/hooks` بحالته وسببه ورمز الردّ.
- `POST /api/hooks/retry` يعيد محاولة كل ما لم يصل.
- **تعثّر الوجهة لا يُفشل إنشاء الرابط** — المدير يحصل على رابطه ويرسله يدويًا
  إن لزم، والأتمتة تلحق لاحقًا.

## بلا ضبط

إن تُركت `MAWSOOL_WEBHOOK_URL` فارغة، لا يُكتب شيء في الصندوق ولا يتغيّر
سلوك النظام إطلاقًا. الأتمتة إضافة لا اعتماد.

## الاختبارات

`test/hooks.test.js` يرفع خادمًا يلعب دور n8n ويتحقّق من التوقيع كما يجب أن
يتحقّق المستقبل الحقيقي — فهو وصف تنفيذي للعقد لا للتنفيذ. يغطّي: كفاية
الحمولة، وصحّة التوقيع، ورفض السرّ الخاطئ، وبقاء الحدث في الصندوق عند تعثّر
الوجهة ثم نجاحه بعد التعافي، والامتناع عن الإرسال بلا سرّ، وقصر الصادر على
المدير.
