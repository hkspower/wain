# نظام موصول لإدارة المندوبين

نظام تشغيلي كامل بالعربية يدير طلبات التوصيل ويسمح للمندوبين **بتحويل الطلبات بينهم**
بموافقة الطرف المستلِم. مبني بـ Node.js و SQLite بلا أطر عمل خارجية وبلا خطوة بناء.

---

## التشغيل

```bash
cd agent-system
npm install
npm run seed        # بيانات تجريبية (يتخطّاها إذا كانت القاعدة غير فارغة)
npm start           # http://localhost:4000
```

| متغيّر البيئة | الغرض | الافتراضي |
|---|---|---|
| `PORT` | منفذ الخادم | `4000` |
| `HOST` | عنوان الاستماع | `0.0.0.0` |
| `MAWSOOL_DB` | مسار ملف قاعدة البيانات | `data/mawsool.db` |
| `MAWSOOL_DATA_DIR` | مجلد البيانات | `data/` |
| `MAWSOOL_SECURE_COOKIE` | اجعلها `1` خلف HTTPS | معطّل |

أوامر أخرى: `npm run reset` (إعادة بناء البيانات التجريبية من الصفر)، و`npm test`.

### حسابات البداية

| الدور | المستخدم | كلمة المرور |
|---|---|---|
| مدير عمليات | `admin` | `admin1234` |
| مندوبون | `ahmad` · `yousef` · `fahad` · `bader` · `meshari` | `agent1234` |

> **غيّر كلمات المرور هذه قبل أي استخدام حقيقي.** أنشئ مديرًا جديدًا من شاشة
> «المندوبون» ثم عطّل الحسابات التجريبية.

## الأدوار والصلاحيات

**مندوب التوصيل** يرى طلباته فقط، ويحرّك حالتها، ويطلب تحويلها لزميل، ويردّ على
التحويلات الواردة إليه، ويغيّر حالة توفّره (متاح / مشغول / غير متصل).

**مدير العمليات** يرى كل شيء: ينشئ الطلبات ويسندها، ويعيد التوزيع مباشرةً بلا
انتظار موافقة، ويدير حسابات المندوبين، ويطّلع على إحصاءات اليوم.

الصلاحيات مفروضة في الخادم على كل نقطة نهاية — لا يكفي إخفاء الأزرار في الواجهة.

---

## دورة حياة الطلب

```
جديد ← مُسند لمندوب ← قبِله المندوب ← تم الاستلام ← في الطريق ← تم التسليم
                                                        └→ تعذّر التسليم ⇄ في الطريق
                                                                    └→ مرتجع
```

- المندوب ملزم بالتسلسل أعلاه — لا يستطيع القفز من «مُسند» إلى «تم التسليم».
- **«تعذّر التسليم» يتطلب كتابة سبب** وإلا رُفض الطلب.
- الحالات النهائية (تم التسليم، مرتجع، ملغي) لا تقبل أي تغيير بعدها.
- مدير العمليات يستطيع الانتقال لأي حالة عدا العودة من حالة نهائية.

## تحويل الطلبات بين المندوبين

هذه هي الميزة المحورية، وقاعدتها: **الطلب لا ينتقل بمجرد الضغط على «تحويل».**

1. المندوب يفتح طلبًا مسندًا إليه ← «تحويل لزميل» ← يختار المندوب ويكتب السبب.
2. يُنشأ طلب تحويل بحالة *معلّق*، **والطلب يبقى في عهدة صاحبه**.
3. الزميل يراه في «التحويلات ← محوّلة إليّ» فيقبل أو يرفض مع ملاحظة.
4. عند **القبول** ينتقل الطلب فعليًا. عند **الرفض** يبقى مع صاحبه.
5. صاحب الطلب يستطيع **سحب** طلب التحويل قبل ردّ الزميل.

القواعد المفروضة في الخادم:

- طلب تحويل معلّق **واحد فقط** لكل طلب — مضمون بفهرس فريد في قاعدة البيانات
  (`ux_transfers_one_pending`) وليس بفحص في الكود فقط.
- لا يُقبل التحويل إلا من المندوب المقصود (أو المدير)، ولا يُسحب إلا من صاحبه.
- لا يمكن التحويل إلى المندوب نفسه، ولا لمندوب معطّل.
- لا يمكن تحويل طلب في حالة نهائية.
- **إنهاء الطلب يُلغي طلب التحويل المعلّق تلقائيًا** حتى لا يبقى معلّقًا للأبد.
- إذا كانت الشحنة **مستلمة فعليًا** وقت التحويل، تبقى الحالة «تم الاستلام» بعد
  انتقالها (مناولة يدوية بين المندوبين)، وإلا تعود إلى «مُسند» ليقبلها المندوب الجديد.
- إعادة الإسناد من المدير تُلغي أي تحويل معلّق على الطلب.

كل خطوة تُسجَّل في **سجل الطلب** مع المنفّذ والوقت والملاحظة — سجل غير قابل للتعديل.

## البنية

```
agent-system/
├── server/
│   ├── index.js      # خادم HTTP، توجيه المسارات، الملفات الثابتة
│   ├── api.js        # نقاط النهاية تحت /api
│   ├── domain.js     # قواعد العمل: دورة الحياة والتحويل (المصدر الوحيد للحقيقة)
│   ├── auth.js       # scrypt للكلمات، جلسات في قاعدة البيانات، حدّ المحاولات
│   ├── db.js         # المخطّط والفهارس
│   ├── seed.js       # بيانات البداية
│   └── lib/http.js   # أدوات الطلب/الرد والتحقق من المدخلات
├── public/           # الواجهة (HTML + CSS + JS بلا أطر عمل)
├── test/api.test.js  # ٢٦ اختبارًا على الواجهة البرمجية الحقيقية
└── data/             # قاعدة البيانات (خارج git)
```

`domain.js` هو موضع كل قرار يغيّر حالة طلب؛ الواجهة البرمجية تتحقق من المدخلات
وتفوّض القرار إليه، فلا تتكرّر القواعد ولا تتناقض.

## الواجهة البرمجية

| الطريقة | المسار | الوصف |
|---|---|---|
| `POST` | `/api/auth/login` · `/logout` | تسجيل الدخول والخروج |
| `GET` | `/api/auth/me` | بيانات المستخدم الحالي |
| `GET` | `/api/meta` | القوائم الثابتة (الحالات، المركبات، المحافظات) |
| `GET` | `/api/orders` | الطلبات — `scope`, `status`, `q`, `governorate`, `agent_id` |
| `POST` | `/api/orders` | إنشاء طلب *(مدير)* |
| `GET` | `/api/orders/:id` | تفاصيل الطلب مع سجله وتحويلاته |
| `PATCH` | `/api/orders/:id/status` | تغيير الحالة |
| `POST` | `/api/orders/:id/assign` | إسناد مباشر *(مدير)* |
| `POST` | `/api/orders/:id/transfer` | طلب تحويل لزميل |
| `GET` | `/api/transfers` | `box=inbox` أو `outbox` |
| `POST` | `/api/transfers/:id/accept` · `/reject` · `/cancel` | الردّ على التحويل |
| `GET` | `/api/agents` · `POST` · `PATCH /:id` | المندوبون *(الإنشاء والتعديل للمدير)* |
| `PATCH` | `/api/me/availability` | تغيير حالة التوفّر |
| `GET` | `/api/stats` | إحصاءات اليوم |

المصادقة عبر كوكي جلسة `HttpOnly` + `SameSite=Lax`. كل الاستجابات JSON، ورسائل
الأخطاء بالعربية جاهزة للعرض على المستخدم مباشرة.

## الأمان

- كلمات المرور بـ **scrypt** (ملح عشوائي لكل حساب) ومقارنة ثابتة الزمن.
- الجلسات رموز عشوائية ٣٢ بايت مخزّنة في القاعدة، صلاحيتها ١٤ يومًا، وتُنظَّف دوريًا.
- **تعطيل الحساب يُنهي جلساته فورًا** (مغطّى باختبار).
- حدّ ٨ محاولات دخول فاشلة لكل (عنوان IP + مستخدم) خلال ١٠ دقائق.
- كل استعلامات SQL مُعاملية (parameterized) — لا بناء نصوص من مدخلات المستخدم.
- حدّ ٢٥٦ ك.ب لحجم الطلب، ومنع الخروج من مجلد `public` في تقديم الملفات.
- الواجهة تُهرّب كل نص يُدرج في HTML.
- لا يمكن تعطيل آخر مدير في النظام.

### قبل النشر على الإنترنت

1. غيّر كل كلمات المرور التجريبية.
2. شغّل النظام خلف HTTPS واضبط `MAWSOOL_SECURE_COOKIE=1`.
3. ضع الخادم خلف وكيل عكسي (nginx/Caddy) وفعّل نسخًا احتياطيًا دوريًا لملف
   `data/mawsool.db` (وملفات `-wal` و`-shm` معه).
4. النظام يعمل على خادم واحد؛ للتوسّع الأفقي تحتاج نقل القاعدة إلى Postgres.

## ما هو غير مشمول

هذه الحدود مقصودة وواضحة، لا نواقص مخفية:

- **لا تتبّع GPS مباشر** — الحالات تُحدَّث يدويًا من المندوب.
- **لا إشعارات فورية** (push/WebSocket) — الواجهة تحدّث العدادات كل ٤٥ ثانية.
- **لا رفع صور** لإثبات التسليم أو توقيع المستلم.
- **لا تكامل مع الموقع التعريفي** في `website/` — نموذج الطلب هناك ما زال تجريبيًا
  ولا يُنشئ طلبًا في هذا النظام؛ ربطه يحتاج نقطة نهاية عامة ومفتاح وصول.
- **لا تقارير محاسبية** أو تسوية تحصيل المندوبين.
